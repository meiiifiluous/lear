# Codex Reconnecting 代理配置提示词（macOS）

请帮我解决“不打开 TUN 模式时 Codex 一直显示 `Reconnecting`”的问题，并严格按照以下步骤执行：

1. 先进行只读检查，确认本机代理客户端当前监听的本地代理端口。优先识别 HTTP 代理端口或 Mixed 混合端口，不要把 SOCKS5 端口、控制端口或 API 端口误当成 HTTP 代理端口。

2. 检查 `~/.codex/.env` 是否存在。目标文件必须位于当前登录用户的主目录，例如：

   ```text
   /Users/<当前用户名>/.codex/.env
   ```

   不要写入当前项目目录中的 `.codex/.env`，也不要把示例用户名硬编码为实际用户名。

3. 如果 `~/.codex/.env` 不存在，可以准备新建；如果已经存在，只修改、替换或追加代理相关变量，必须保留所有无关内容。

4. 在真正创建或修改文件前，先向我完整展示：

   - 解析后的目标文件绝对路径；
   - 检测到的代理端口类型；
   - 代理端口号；
   - 文件当前是否存在；
   - 准备写入或更新后的完整文件内容；
   - 将删除或替换哪些已有代理变量。

5. 如果检测到 HTTP 代理端口或 Mixed 混合端口，准备写入以下变量，其中 `<PORT>` 必须替换成实际检测到的端口号：

   ```env
   HTTP_PROXY=http://127.0.0.1:<PORT>
   HTTPS_PROXY=http://127.0.0.1:<PORT>
   http_proxy=http://127.0.0.1:<PORT>
   https_proxy=http://127.0.0.1:<PORT>
   NO_PROXY=localhost,127.0.0.1,::1
   no_proxy=localhost,127.0.0.1,::1
   ```

   此时不要额外写入 `ALL_PROXY` 或 `all_proxy`，除非现有应用有经过验证的明确需求。

6. 如果只检测到 SOCKS5 代理端口，不要直接写入 `ALL_PROXY`。立即停止并告诉我：当前只发现 SOCKS5 端口，建议先在代理客户端中开启 HTTP 代理端口或 Mixed 混合端口，开启后再重新检测。

   只有在我明确回复“无法开启 HTTP/Mixed，请使用 SOCKS5 兜底方案”后，才允许准备写入：

   ```env
   ALL_PROXY=socks5://127.0.0.1:<PORT>
   all_proxy=socks5://127.0.0.1:<PORT>
   NO_PROXY=localhost,127.0.0.1,::1
   no_proxy=localhost,127.0.0.1,::1
   ```

7. 在我明确确认之前，不得创建、修改、覆盖或删除任何文件。收到确认后才执行写入，并完成以下交付：

   - 只读复核目标文件的最终内容；
   - 确认代理端口仍在监听；
   - 告诉我如何完全退出并重启 Codex；
   - 给出验证 `Reconnecting` 是否消失的方法；
   - 给出恢复到修改前内容的准确回滚步骤。

如果检测结果与我的假设冲突，以实际只读检测结果为准，但仍必须停在写入确认闸门前等待我的明确授权。
